## CORRECTION02 SUMMARY

The original close report documented CORRECTION01's five fixes (ABSENT-vs-INVALID, contract compatibility, writer claims, file inventory, canonical gate execution). This CORRECTION02 addresses two remaining fail-closed defects identified during review:

- **C1 — Unknown GateSourceValidity fails closed**: `EvaluateGateEvidenceBinding` previously had a `switch` that handled `SourceAbsent` and `SourceInvalid` but fell through to the valid-evidence path for any other numeric value (including unhandled enum values like `GateSourceValidity(99)`). The classifier's own doctrine (`AMBIGUOUS_BINDING_FAILS_CLOSED=true`) was violated. Fixed by adding an explicit `case SourceValid:` and a `default:` that returns `EVIDENCE_INVALID`.
- **C2 — `parent_act` is no longer usable as scope identity**: `digestScopeBinding` previously fell back to `gate.ParentAct` when `gate.ScopeID` was empty. This let a gate summary that is a child of `ACT-A` (parent_act=ACT-A, scope_id="") be bound as authoritative for a digest with `ActID=ACT-A`. Fixed by removing the fallback: only `gate.ScopeID` establishes scope match. `ParentAct` remains rendered as provenance metadata but does not establish authority.

New regression coverage:

- `TestEvaluateGateEvidenceBinding_Matrix` rows 17 (unknown validity) and 18 (parent_act-only).
- `TestGateSummary_ParentActOnlyDoesNotMatchScope` — pure classifier-level proof that the substitution defect cannot recur.
- `TestGateSummary_DigestScopeBindingParentActOnly` — lowest-level regression on the `digestScopeBinding` function.

The CORRECTION01 fixes remain in place.

## BEHAVIOR CHANGED

### C1: Unknown GateSourceValidity fails closed

Before CORRECTION02: `EvaluateGateEvidenceBinding(gate, digest, GateSourceValidity(99))` could reach the valid-evidence path. If the gate had matching HEAD/scope, the classifier returned `AUTHORITATIVE=true`, which directly violated `AMBIGUOUS_BINDING_FAILS_CLOSED=true`.

After CORRECTION02: any value other than `SourceAbsent`, `SourceInvalid`, `SourceValid` short-circuits to `EVIDENCE_INVALID` with `authoritative_for_digest=false`. The `default:` branch is explicit and fail-closed.

### C2: parent_act no longer establishes scope match

Before CORRECTION02: a gate summary with `scope_id=""` and `parent_act="ACT-A"` was treated as having `gateScope="ACT-A"` for scope comparison. A digest with `ActID="ACT-A"` and matching execution HEAD would become `AUTHORITATIVE`. The classifier effectively claimed authority on provenance metadata, not on actual scope identity.

After CORRECTION02: `gateScope` is taken only from `gate.ScopeID`. The `parent_act` is preserved as provenance metadata (rendered as `gate_parent_act=...`) but cannot establish scope match. The same fixture now produces `STATE_MATCH_SCOPE_UNBOUND` with `authoritative_for_digest=false`.
