## §1 — prescribed 14-flag × 4-form duplicate matrix

This is a **prescribed-form** matrix, not a Cartesian
matrix. The 56 rows are 14 flags × 4 prescribed
duplicate forms. Each row is one (flag, form) pair.
The form is an explicit pair of spellings the
duplicate detector MUST reject with exit 2 and the
canonical flag name.

A true Cartesian matrix over four spellings would
produce 14 × 4 × 4 = 224 rows and is not what this
ACT requires.

The closed set of public flags declared in
`v2VerifierScalarFlagNames` is:

```text
1.  repository
2.  protocol-version
3.  plan-contract-version
4.  subject
5.  freeze
6.  closure
7.  plan-path
8.  manifest-path
9.  working-manifest-assertion
10. expected-tag
11. output
12. json
13. capture-caller-state
14. help
```

The four prescribed duplicate forms for value flags:

```text
F1  --flag value  --flag value
F2  --flag=value  --flag=value
F3  -flag  value  --flag value
F4  -flag=value   --flag=value
```

The four prescribed duplicate forms for boolean
flags:

```text
BF1 --flag --flag
BF2 --flag=true --flag
BF3 --flag --flag=true
BF4 -flag --flag
```

Go's `flag` package accepts either one or two leading
dashes, and Boolean flags do not require an explicit
value. Therefore `-json --json` is two valid
occurrences; the duplicate detector must reject it
with `exit 2` and the canonical `duplicate_cli_flag`
diagnostic naming `json`. Form BF4 is therefore a
duplicate form, not a stdlib parse failure.

A genuinely awkward Boolean form is:

```text
-json true --json
```

because `true` becomes a positional argument rather
than the Boolean flag's value. That form is covered
by the public-negative matrix §2 (usage error) and
not by the duplicate matrix §1.

The full matrix size is:

```text
11 value flags × 4 prescribed forms = 44 rows
3  boolean flags × 4 prescribed forms = 12 rows
```

Total: 56 rows. Each row:

```text
name             string
args             []string
flagName         string
exit             2
diagnosticCode   closure.V2VerifierDuplicateCLIFlag
canonicalName    in diagnostic message
```

The matrix is generated by a Go helper:

```text
func generateV2VerifierDuplicateMatrix() []v2VerifierDuplicateFlagCase
```

The helper lives in a new test file
`factory_close_v2_verifier_duplicate_matrix_test.go`
and is consumed by both
`TestV2VerifierDuplicateFlagMatrix` and the
`TestV2VerifierDuplicateBooleanFlags` table-driven
loop. The hand-written table that exists today is
deleted; only the generated table remains.

A separate test asserts the table size:

```text
if len(generateV2VerifierDuplicateMatrix()) != 56 { ... }
```

This pins `DUPLICATE_MATRIX_PRESCRIBED_COVERAGE=14`
and `DUPLICATE_MATRIX_PRESCRIBED_FORMS_PER_FLAG=4`
on the closed set of 14 flags and the four
prescribed forms.

## §3 — full adversarial trailer / terminal-block cases

The trailer parser is exercised by the following
hermetic tag bodies. Each row asserts the resulting
`tagValid` boolean and the appended diagnostics.

The model is the **mixed terminal trailer suffix**
defined in the primary ACT (Mission 7): the final
non-empty region is a trailer block, non-Leamas
trailers are allowed inside the block, and the seven
Leamas keys must each appear exactly once inside the
block.

```text
T1  trailing blank lines after the trailer block
    -> tagValid=true, diags empty
T2  prose appearing after the trailer block
    -> tagValid=false, diags=[closure_tag_metadata_malformed]
T3  Leamas-Subject-Commit value (no colon)
    -> tagValid=false, diags=[closure_tag_metadata_malformed]
T4  Leamas-Unknown: value outside the terminal block
    -> tagValid=false, diags=[closure_tag_metadata_unknown]
T5  Leamas-Subject-Commit:  value (multiple spaces)
    -> tagValid=false, diags=[closure_tag_metadata_malformed]
T6  a non-Leamas trailer inside the trailer block
    -> tagValid=true, diags empty (mixed model allows it)
T7  an empty final line and multiple final newlines
    -> tagValid=true, diags empty
T8  a Leamas- line in the middle of the message body
    -> tagValid=false, diags=[closure_tag_metadata_malformed]
T9  duplicate Leamas- keys in the trailer block
    -> tagValid=false, diags=[closure_tag_metadata_duplicate]
T10 Leamas-Subject-Commit:value (no space)
    -> tagValid=false, diags=[closure_tag_metadata_malformed]
T11 Leamas-Subject-Commit: <empty>
    -> tagValid=false, diags=[closure_tag_metadata_malformed]
T12 empty tag body
    -> tagValid=false, diags=[closure_tag_metadata_missing]
T13 trailer block with all required keys bound
    -> tagValid=true, diags empty
T14 trailer block missing one required key
    -> tagValid=false, diags=[closure_tag_metadata_missing]
T15 trailer block with one mismatched value
    -> tagValid=false, diags=[closure_tag_metadata_mismatch]
```

The algorithm is documented in the primary ACT
(Mission 7). The support document fixes the
identifier of the diagnostic for each row.

The trailer parser is required to inspect the raw
trimmed line prefix BEFORE invoking
`parseV2ClosureTagTrailerLine`. A line whose raw
prefix is `Leamas-` but whose parsed key is empty
MUST yield `closure_tag_metadata_malformed`.

## §4 — full JSON single-document EOF rationale

The `json.Decoder.Decode` method returns `io.EOF`
when the input stream has no further top-level JSON
value. The `json.Decoder.Token` method returns
`(nil, io.EOF)` only when the input stream is empty;
on token-state errors or partial garbage it returns
a different error, which the current test treats
identically to EOF and is therefore too permissive.

The correct single-document assertion is:

```go
var doc map[string]any
if err := dec.Decode(&doc); err != nil {
    t.Fatalf("decode JSON envelope: %v", err)
}
var ignore any
if err := dec.Decode(&ignore); err != io.EOF {
    t.Fatalf("JSON output must be exactly one document, got err=%v", err)
}
```

The affected test files are:

```text
factory_close_v2_verifier_exit_matrix_test.go
factory_close_v2_verifier_public_negative_test.go
factory_close_v2_verifier_help_contract_test.go
```

Each `dec.Token()` call used as an EOF check is
replaced with the two-`Decode` pattern above. The
test helper `assertJSONIsSingleDocument(t, stdout)`
in a new file
`factory_close_v2_verifier_cli_test.go` provides
the shared implementation.

The contract change is acceptance-bound by:

```text
JSON_EOF_ASSERTION_USES_SECOND_DECODE=true
```

The test that previously passed because
`dec.Token()` happened to return `(nil, io.EOF)`
on a stream with garbage is no longer permitted to
pass for the wrong reason.
